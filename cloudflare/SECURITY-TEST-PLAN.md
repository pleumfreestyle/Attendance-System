# Backend Security and Integration Test Plan

สถานะเอกสาร: ใช้ตรวจ branch `feature/real-attendance-backend` ก่อน merge/deploy

## ข้อห้ามก่อนเริ่ม

- ห้ามใช้คำสั่ง POST/PATCH ที่เปลี่ยนข้อมูลกับ Production ระหว่างทดสอบ
- ใช้ Worker และ D1 สำหรับ staging แยกจาก Production
- ห้ามนำ `JWT_SECRET`, `ADMIN_TEST_KEY`, LINE token หรือ LINE channel secret ไปใส่ในไฟล์ทดสอบ/คำสั่งที่แชร์ต่อ
- ห้ามสร้างบัญชีแอดมินผ่าน endpoint สาธารณะ; ให้ bootstrap ผ่านขั้นตอนควบคุมใน D1 Console และตรวจอีเมลก่อน
- การตรวจไฟล์และเส้นทางไม่ใช่หลักฐานว่า API ทำงานจริง ต้องทดสอบ HTTP กับ staging เพิ่มเติม

## 1. ตรวจค่าตั้งต้น

- [ ] Worker staging มี D1 binding ชื่อ `DB`
- [ ] `JWT_SECRET` เป็น secret ที่สุ่มจริงและยาวอย่างน้อย 32 ตัวอักษร/ไบต์
- [ ] ตั้ง CORS ให้ตรงกับ origin ของ Frontend ที่จะใช้จริง
- [ ] มีสถานที่ทำงานที่ตรวจสอบพิกัดและรัศมีแล้ว
- [ ] มีบัญชีแอดมินที่ผ่านการ bootstrap อย่างปลอดภัย
- [ ] ตรวจว่า migration ที่ต้องใช้ถูกนำไปใช้กับ D1 ของ staging แล้ว
- [ ] บันทึก revision ของ Worker และ schema ที่กำลังทดสอบ โดยไม่บันทึก secrets

## 2. สมัครสมาชิกและเข้าสู่ระบบ

- [ ] สมัครด้วยข้อมูลครบและถูกต้อง ได้ HTTP 201
- [ ] สมัครด้วยอีเมลซ้ำหรือรหัสบุคลากรซ้ำ ได้ HTTP 409
- [ ] สมัครด้วยอีเมลผิดรูปแบบ/รหัสผ่านสั้น/ข้อมูลเกินขนาด ได้ HTTP 400
- [ ] ส่ง JSON ใหญ่เกิน 16 KiB ได้ HTTP 413
- [ ] เข้าสู่ระบบด้วยรหัสผ่านผิด ได้ HTTP 401 โดยไม่เปิดเผยว่ามีอีเมลอยู่หรือไม่
- [ ] บัญชีรออนุมัติและบัญชีถูกระงับไม่สามารถเข้าสู่ระบบได้
- [ ] Token ถูกต้องใช้ได้; token ผิด/หมดอายุ/ถูกยกเลิกใช้ไม่ได้

## 3. สิทธิ์และข้อมูลส่วนบุคคล

- [ ] ไม่มี token เรียก endpoint ที่ต้องเข้าสู่ระบบไม่ได้
- [ ] บัญชี `staff` เรียก endpoint `/api/admin/*` ได้ HTTP 403
- [ ] ผู้ใช้ทั่วไปอ่านประวัติลงเวลาได้เฉพาะของตนเอง
- [ ] การเปลี่ยน role และการระงับบัญชีทำได้เฉพาะแอดมิน
- [ ] ไม่สามารถระงับแอดมินที่กำลังใช้งาน หรือทำให้ไม่มีแอดมินที่ active เหลืออยู่
- [ ] เปลี่ยนรหัสผ่านแล้ว token เก่าถูกยกเลิก
- [ ] ตรวจสอบว่ารหัสผ่านและ temporary password ไม่ถูกเขียนลง log

## 4. การลงเวลาและ GPS

- [ ] ลงเวลาเข้าในพื้นที่ที่อนุญาตและ GPS accuracy ผ่านเกณฑ์ ได้ HTTP 201
- [ ] ลงเวลานอกพื้นที่ ได้ HTTP 403 และไม่เกิดแถวข้อมูลใหม่
- [ ] accuracy มากกว่า 100 เมตรหรือพิกัดไม่ถูกต้องถูกปฏิเสธ
- [ ] ลงเวลาเข้าซ้ำในวันเดียวกันถูกปฏิเสธ
- [ ] ลงเวลาออกก่อนเข้า หรือออกซ้ำถูกปฏิเสธ
- [ ] ส่งคำขอเข้า/ออกซ้ำพร้อมกันหลายครั้ง ต้องมีข้อมูลสำเร็จไม่เกินหนึ่งรายการต่อประเภทต่อวัน
- [ ] ส่งคำขอลาโดยใช้วันที่ไม่มีจริง เช่น `2026-02-30` ต้องได้ HTTP 400
- [ ] ตรวจวันเปลี่ยนวันที่ตามเวลาไทย (Asia/Bangkok) รวมถึงทดสอบวันที่ใกล้เที่ยงคืน
- [ ] ระบุในคู่มือว่าการตรวจ geofence ใช้พิกัดจากอุปกรณ์ จึงไม่สามารถรับประกันการป้องกันการปลอม GPS ได้สมบูรณ์

## 5. คำขอลาและการจัดการบุคลากร

- [ ] ผู้ใช้ส่งคำขอลาที่มีช่วงวันที่ถูกต้องได้
- [ ] ปฏิเสธวันที่ไม่ถูกต้องหรือวันสิ้นสุดก่อนวันเริ่มต้น
- [ ] ผู้ใช้เห็นเฉพาะคำขอลาของตนเอง
- [ ] เฉพาะแอดมินพิจารณาคำขอที่มีสถานะ pending ได้
- [ ] คำขอที่พิจารณาแล้วไม่สามารถเปลี่ยนผลซ้ำได้
- [ ] การอนุมัติบัญชี/เปลี่ยน role บันทึก audit log

## 6. รีเซ็ตรหัสผ่าน

- [ ] อีเมลที่มีและไม่มีในระบบได้รับข้อความตอบกลับสาธารณะที่ไม่เปิดเผยการมีอยู่ของบัญชี
- [ ] เฉพาะแอดมินดู/จัดการคำขอได้
- [ ] คำขอเดียวกันที่ประมวลผลไปแล้วไม่สามารถใช้ซ้ำได้
- [ ] ให้แอดมินสองบัญชีประมวลผลคำขอเดียวกันใกล้เวลาเดียวกัน ต้องเปลี่ยนรหัสผ่านได้เพียงครั้งเดียว และมี audit log ที่สอดคล้อง
- [ ] Temporary password ส่งให้เจ้าของบัญชีผ่านช่องทางที่ตรวจสอบตัวตนได้ และแนะนำให้เปลี่ยนทันที
- [ ] ยืนยันว่าไม่มีการส่ง temporary password ผ่าน LINE group หรือ log โดยไม่ตั้งใจ
- [ ] เพิ่ม rate limiting/การป้องกันการยิงคำขอซ้ำ ก่อนเปิดให้ใช้งานสาธารณะ

## 7. LINE regression — ต้องทดสอบก่อน deploy

- [ ] ส่ง POST ไป `/webhook` พร้อม signature ที่ถูกต้อง ได้ HTTP 200 และ body `OK`
- [ ] signature ผิด/ไม่มี signature ได้ HTTP 401
- [ ] `/test-send` เมื่อไม่มี/ผิด `ADMIN_TEST_KEY` ได้ HTTP 401
- [ ] ทดสอบ push message ไปยัง LINE Group ที่ถูกต้องจาก staging โดยผู้ดูแลอนุญาต
- [ ] ตรวจว่าการทดสอบไม่เปลี่ยน LINE secrets หรือพฤติกรรม webhook เดิม
- [ ] ยืนยันกับผู้ดูแลว่าข้อความทดสอบได้รับจริง ก่อนเปลี่ยน Worker production

## 8. ผลการทดสอบ

บันทึกแต่ละรายการเป็น `ผ่าน`, `ไม่ผ่าน` หรือ `ยังไม่ได้ทดสอบ` พร้อมวันเวลา, revision, HTTP status และรายละเอียดที่ไม่เป็นความลับ

**เกณฑ์ก่อน merge/deploy:** ไม่มีข้อผิดพลาดระดับวิกฤต/สูงค้างอยู่, ผ่านการทดสอบสิทธิ์และการลงเวลาซ้ำ, ทดสอบ LINE regression ผ่าน และมีวิธี rollback ที่ตรวจสอบแล้ว
